# 編集システム

## 企画評価

候補を次の観点で比較する。点数は採否を自動決定するものではなく、判断理由を残すために使う。

| 観点 | 確認内容 |
|---|---|
| 実体験 | 自分で経験、制作、取材、観測した内容があるか |
| 視聴者価値 | 視聴者の判断または作業が具体的に変わるか |
| 根拠 | 分野に合う一次資料と確認方法を確保できるか |
| 視覚性 | 写真、映像、比較、データ、図で理解を助けられるか |
| 新規性 | 既存解説と異なる問いまたは切り口があるか |
| 適時性 | 今扱う理由と情報の有効期限が明確か |
| 制作費 | 調査、撮影、権利処理の負担に見合うか |

検索需要だけでテーマを選ばない。本人が知りたいことを調査して自分用の学習回を作り、公開価値があるものだけ公開候補へ昇格させてもよい。

## 調査とclaim

優先順位:

1. 原資料、公式記録、一次データ、原論文、法令、権利者または当事者の発表
2. 自分で実施した取材、撮影、観測、実演
3. 編集責任と根拠が明確な二次資料
4. 専門家の解説やレビュー
5. コミュニティ投稿やSNS。話題と体験談の発見に使い、検証可能な事実の唯一の根拠にしない

一次資料の形は分野ごとに異なる。商品比較ではメーカー情報と実測、歴史では史料と研究、ニュースでは当事者発表と現地報道、教育では原典と標準的資料を優先する。体験談では本人の記録を一次資料として扱い、一般化できる事実とは分ける。

claimの分類:

- `fact`: 外部検証できる事実。原則としてsource IDが必要
- `observation`: 取材、撮影、測定、実演、体験による観測結果。条件、方法、日時を記録
- `inference`: 複数の事実から導いた解釈。推論であることを台本でも示す
- `opinion`: 制作者の評価や好み。主語と判断基準を示す

価格、日付、役職、統計、引用、提供範囲、利用条件など変化または誤認しやすい情報は公開直前に再確認する。画面へ出す数値と台本で読む数値の出典を同じclaimへ結び付ける。

## 台本設計

冒頭で結論をすべて読み上げず、視聴者の問い、意外な差分、検証結果のいずれかを具体的に示す。抽象的な危機感や根拠のない最上級表現を使わない。

セリフ単位の原則:

- 一つのセリフで一つの役割
- 音声で追える長さと構文
- 固有名詞、数値、引用、専門用語を画面で補助
- 相づちは理解、反論、要約、次の問いのいずれかを担う場合だけ残す
- 重要な制約を動画末尾へ隠さない
- CTAは視聴者が次に取れる行動と動画内容を接続する

二人構成を使う場合は単なる交互読み上げを避ける。例として一人を視聴者の疑問と反例、もう一人を説明と検証の担当にする。役割、知識差、口調、禁止表現を`channel.json`へ定義する。

## ビジュアルライブラリ

分野を問わず再利用しやすい型:

- `hook`: 冒頭の結果、違和感、問い
- `question`: 問い、誤解、結論の予告
- `hero`: 主題となる人物、場所、商品、作品
- `comparison`: 2列比較、選択条件、before/after
- `quote`: 発言、文章、レビューの短い引用
- `stat`: 数字と出典
- `timeline`: 経緯、工程、時間変化
- `map`: 場所、移動、分布
- `diagram`: 関係、構造、仕組み
- `steps`: 手順、チェックリスト
- `source`: 根拠資料の該当箇所
- `demo`: 実物、実演、操作、観測結果
- `photo`: 写真と注釈
- `clip`: 動画クリップと注釈
- `illustration`: 認知負荷を下げる補助絵
- `code`、`terminal`: 技術や操作手順を扱う場合の追加型

各テンプレートへ文字数上限、安全領域、許容する要素数、配色トークン、アニメーション規則を持たせる。強調方法を限定し、色、太字、囲みを同時に重ねない。汎用テンプレートの見た目をチャンネル固有の表現として無調整で流用しない。

生成画像へ文字を焼き込まず、背景、文字、キャラクターを別レイヤーとして扱う。画像生成を使う場合はスタイルを形容詞だけで伝えず、輪郭、塗り、色数、比率、禁止要素、キャラクターの不変条件を明示する。

## サムネイルとタイトル

タイトル候補は最低3案を作り、次を比較する。

- 固有名詞または検索語
- 視聴後に分かること
- 他の動画との差
- 誇張なしで生じる好奇心

「時代が来た」「すごすぎる」など対象を特定しない表現を単独で使わない。サムネイルの文言は最大2まとまりとし、タイトルの全文を繰り返さない。背景候補、文言候補、構図候補を分けて比較する。最終案は人間が小サイズで確認する。

## Shorts

本編の要約ではなく入口として設計する。

1. 0〜2秒: 固有名詞、結果、問いのいずれか
2. 本文: claimを1つに絞った説明、観測、実演のいずれか
3. 終端: 判断材料または本編を見る理由

縦画面用template ID、字幕位置、文字数、切り替え速度を別に定義する。本編と同じアセットを使う場合もトリミング位置と情報量を再確認する。

## 翻訳

マスター台本の承認後にセリフ、画面文言、タイトル、説明文、サムネイル文言だけを抽出して翻訳する。URL、固有名詞、source ID、レイアウト設定など翻訳不要のデータをモデルへ渡さない。各言語で口調、意味の忠実性、自然さ、文字量をレビューする。人間が確認できない言語では公開範囲を明示し、誤り報告を受け取る導線を用意する。
