# コアQのセット制作

coreq-video-studioの既存機能を使い、対象問題の学びを長尺・短尺・Xへ展開する。001の完成文言や数値をコピーせず、工程と検査を再利用する。

## 着手と再開

1. 現在の指示とリポジトリのAGENTS.mdを確認する。対象は科目＋問題IDで特定する。「002」だけなら会話の科目を引き継ぎ、分からなければ確認する。全科目を財務・会計として扱わない。
2. `coreq-video-studio`、必要に応じて`catchup-studio`と`shindanshi-app`のルートを既存コンテキストから解決する。保存済みの端末絶対パスを前提にしない。
3. 次の読み取り専用スクリプトで既存成果物と不足を調べる。`<skill-dir>`はこのスキルのディレクトリ。レポートの再利用候補は適用可否の合格判定ではない。

```bash
node <skill-dir>/scripts/inspect-set.mjs <video-repo>/channels/demo exam-accounting-002
```

4. 毎回チャンネルの`QUALITY.md`で図解演出の方針を確認し、`STRUCTURE.md`、`PRODUCTION-PLAN.md`を必要な部分だけ読む。対象の`plans/curriculum/curriculum.json`行と現在の教材を照合する。カリキュラムの正規化ハッシュとepisodeのraw SHA-256は別方式なので直接比較しない。
5. 既存の作業票があれば参照し、現在の原本・ジョブと突き合わせて再開地点を更新する。生成済みで版が一致する動画を理由なく再生成しない。未作成、古い版、確認待ちを区別する。

## 1セットの制作

- 通し番号順を基本に1セットずつ進める。基礎編は必要な論点と条件を満たす既存動画があれば再利用する。ファイル名の番号一致だけで適用可否を判断しない。
- 学習内容の原本はshindanshi-app、学習セットの設計はcatchup-studio、台本・図解は各episode。公開文言は既存の`draft.json`／`episode.delivery`／`x-post.json`を使い、確認ページを編集原本にしない。
- 新しい台本の制作は合意済みのSol制作→Astraレビューを使う。担当への入力は対象原典・版・必要な基準・変更範囲・出力先に絞る。単純な文言や素材の集約はメインで処理する。モデルが利用できなければ代替とレビュー範囲を明示し、実行したモデルを偽らない。重いレンダリングは逐次実行する。
- 基礎編はキューとトイの掛け合い、問題解説はキューと原問を解く形式。略語の正式名称・日本語の意味、式の理由、適用条件、理解確認、最後のまとめを保つ。横動画の共通導入はチャンネル設定を使う。内容に必要な尺を優先し、8分前後なら8分以上を検討する。
- 数式の展開、資金の流れ、グラフの変化など動きが理解を助ける場面では、説明に同期した矢印・式の段階表示を優先する。Remotionを補助レンダラーの第一候補にし、対象教材の数値・単位・条件と既存の音声・字幕・キャラクターを保つ。静止画で十分な場面に動きを義務化しない。採用例と組み込み時の検査は[図解アニメーションの制作](references/workflow.md#図解アニメーションの制作)を読む。
- 短尺は独立した問い1つに絞り、縦画面用に再構成する。30〜60秒を目安としつつ、説明に必要なら理由を記録して90秒以内へ収める。ShortsとTikTokのMP4は共用し、投稿文を分ける。Xは文章＋図解を基本とする。X用の別動画やInstagram展開を毎回追加しない。今回の依頼に含まれない派生を義務化しない。
- 制作操作と版の扱いは[媒体別の実行手順](references/workflow.md)を必要な工程から読む。
- モデルの分担と入力の絞り方は[トークン効率を考慮した分担](references/workflow.md#トークン効率を考慮した分担)に従う。制作と独立レビューの2担当までにし、同じ調査を担当ごとに繰り返さない。

## 品質と引き渡し

台本の合格を完成映像の合格に流用しない。原典・独立検算、表示と読み、最終MP4の全セリフ代表フレーム、非無音・全編デコード、キャラと発話、端末幅での判読を確認する。短尺やXは適用する採点項目を事前に定め、長尺セットの採点をそのまま当てない。根拠がない90点を付けない。

生成成功、AI編集評価、本人の試聴、公開承認、公開済みを分ける。本人未確認ならレビューAPIを呼ばず、下書きページまで完成させる。投稿・公開予約・アップロードは明示的な依頼がある場合に限る。既存の制作承認でローカル作業を進め、各工程で同じ許可を聞き直さない。

完成時は再生・編集・媒体別確認のリンク、固定したepisode版とjob ID、検証範囲、未確認事項、次の再開地点を残す。作業票は[記録項目](references/workflow.md#作業票の記録項目)を使う。消費トークンや費用を取得できなければ未計測と記録し、経過時間から推測しない。
