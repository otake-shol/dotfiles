# 意図と利用者負担のデザインレビュー

図解・スライド・アプリUIで構成や表現を選ぶ前と、完成物を確認するときに使う。
この文書は各制作スキルから参照する媒体共通の原則であり、独立した実行スキルではない。
変更対象に関係する項目だけを適用し、小さな修正を全面再設計へ広げない。
媒体固有のブランド、トークン、文字サイズ、検証手順は各スキルの正本に従う。

## 制作前の判断

既存のbrief、構成案、アプリプロフィールなどの制作メモに次を短く残す。
新しい管理ファイルや承認工程は増やさず、成果物の本文には制作メモを出さない。

- **相手と場面**: 誰がどの表示環境で何を理解・判断・操作するか。
- **優先順位**: 最初に伝える情報または操作と、後から参照できればよい情報。
- **選択理由**: 今回選ぶ構成や表現が内容の関係や利用場面にどう役立つか。

依頼や既存仕様から分かる条件を使う。未確定でも可逆的な選択なら仮定を明記して進める。
ブランドの継承、慣れた操作、一貫した比較も有効な選択理由になる。
独自性を出すためだけに既存のデザインシステムや標準操作を崩さない。

例: 科目別の復習一覧では同じ項目を比較できる行レイアウトを使い、
未復習の状態をラベルで示す。全科目を同じ大きな宣伝カードにする必要はない。

## 表現選択の見直し

特定の色・フォント・角丸・カードを一律禁止しない。次の組み合わせを見つけたら
目的との対応を確認し、理由のない要素を整理する。

| 兆候 | 確認と修正 |
| --- | --- |
| 紫グラデーション、ピル型バッジ、3枚カードを内容によらず採用 | バッジの意味、情報の区切り、読む順番を確認。比較なら表、手順なら流れ、独立した操作ならカードを候補とし、関係から選び直す |
| AIらしさを避けるために黒背景・グロー・方眼・Bentoへ一括変更 | 色を替える前に階層と内容を見直す。既存ブランドや表示条件に合う表現は維持する |
| 汎用コピーやイラストだけで題材を説明 | 利用者の具体的な作業、対象、得られる結果を示す。実画面や実データを使うなら出典と条件を確認し、証拠を捏造しない |
| すべてを枠・矢印で結び、縮小して1枚に収容 | 今回判断する関係を残し、詳細を別図・付録・ノートへ移す。配布資料でも検索・参照できる本文を残す |
| 透過・影・動きで文字や操作状態が判別しづらい | 実際の背景と状態で確認し、必要に応じて不透明な面、ラベル、境界を使う。装飾を外しても状態と操作を識別できるようにする |
| 自動切替やポップアップが読む・解く・選ぶ作業を遮る | 利用者が開始時点を選べる形を検討。必要な表示でも閉じ方・停止・再開を確認し、複数の要求を同時に重ねない |

## 選択と操作の公平性

UIを扱う場合だけ適用する。図解やスライドに同意フローを追加しない。

- 通知、同意、登録などを求める前に、その時点で必要な理由を確認する。
- 拒否・後で・取消が可能な場面では選択肢を見つけやすくし、同意だけを目立たせて
  拒否を小さな文字や余分な手順へ追いやらない。これは同意設計の原則であり、通常の主操作と副操作を同じ強さにする指示ではない。
- 設定変更や離脱の経路を確認し、文言と実際の操作結果を一致させる。
  法的な適合性はこの見た目のレビューだけでは判定しない。

## 完成物の確認

制作意図を知っていることと、初見で使えることを分けて確認する。

1. 説明を読まずに成果物を見て、最初に分かる内容と次の操作を確認する。
2. 図解・スライドは実際の掲載・投影サイズで主張、ラベル、出典を確認する。
   UIは変更した主要操作を完了し、関連する長文・空・エラー・選択状態も確認する。
3. 対応する画面幅、テーマ、文字拡大で読む順番と可読性を確認する。
   動きがあるUIではReduced Motionと停止手段も確認する。
4. 各スキルの機械検査と目視検査を行い、読みづらさや操作の妨げを修正する。
   見た目の好みだけの指摘と、利用を妨げる不具合を区別する。

報告には対象ページ・画面、確認した条件、修正点、未確認事項を残す。
生成やlintの成功を実利用確認の代わりにせず、未確認項目を合格と記載しない。
