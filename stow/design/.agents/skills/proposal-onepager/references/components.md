# 本文で使える部品（pandoc の fenced div）

frontmatter の `title`・`to`・`date`・`author`・`footer-left`・`footer-right` がヘッダーとフッターに入る。
本文は次の部品を上から並べる。見本は `assets/example.md`。

| 部品 | 書き方 | 用途 |
|---|---|---|
| リード | `::: lead` | 冒頭の 2〜3 行。相手の状況と、この提案の位置づけ |
| 並列の項目（2×2） | `:::: grid4` の中に `::: item`（1 段落目＝項目名、2 段落目＝説明） | 順番のない 4 項目。番号は付けない |
| 成果物の帯 | `::: band`。成果物名は `**太字**` | 手元に残るもの。面で分けるのはここだけ |
| 流れ | `:::: flow` の中に `::: step`（3 段落：補足ラベル・名前・説明） | 時間の順番。番号は自動で付く |
| 料金 | `:::: price` の中に `::: col` と `::: cond` | 枠の中は「今回の内容と価格」だけ |
| 料金のラベル・金額 | `[今回のご提案]{.label}`、`[40,000円[（税込）]{.tax}]{.big}` | 金額は Plus Jakarta Sans になる |
| 枠の外の補足 | `::: note` | 比較の対象（詳細版の価格など）を 1 行で |
| お願い | `::: ask` | 事例掲載など。条件と混ぜない |
| 横並びの選択肢 | `:::: cards` の中に `::: card`（1 段落目＝見出し、`*目安*`） | 診断の後の選択肢など。箱にせず線で分ける |
| 事務的な条件 | `::: terms` の中に箇条書き | 支払い・インボイス・利用料・専門家の確認など。最後にまとめる |

## 書き方の注意

- 区切りのコロンは外側ほど多くする（`:::::` ＞ `::::` ＞ `:::`）
- クラスなしの `::: {}` は使わない（pandoc が外してレイアウトが崩れる）
- 見出し（`##`）で始まる div は pandoc が `<section>` に変える。部品の中に見出しを入れない
