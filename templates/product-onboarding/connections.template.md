# 接続台帳

以下は調査対象の候補一覧。MCPの存在や全機能への対応を示す一覧ではない。導入時に公式資料と組織の提供環境を確認し、実際に利用可能な操作だけを記入する。

## 接続カード

利用する接続ごとに以下を複製する。

### conn-<識別子>

| 項目 | 入力 |
| --- | --- |
| サービス・利用目的 | <入力> |
| 接続方式 | <組織提供コネクター / 公式MCP / 組織承認済みMCP / 手動参照> |
| 提供者・正式名称 | <入力> |
| 公式設定手順URL・確認日 | <入力> |
| 利用クライアント・バージョン | <入力> |
| サーバーURLまたはパッケージ・バージョン | <秘密を含まない接続情報のみ> |
| 認証方式 | <OAuth / その他の組織指定方式 / 未確認> |
| アカウント・組織・リージョン | <入力> |
| 設定の保存場所 | <勤務先で許可された場所。秘密値は記載しない> |
| 必要な権限と理由 | <検索・閲覧に必要な実際のスコープ名と理由> |
| 実際に付与された権限 | <認証画面や管理設定で確認した範囲> |
| 有効にするツール | <実際に公開されたツール名> |
| 書き込み操作の制限方法 | <サーバー側スコープ / クライアント側の無効化など> |
| 許可対象 | <チャンネル・フォルダ・プロジェクト・環境など> |
| 検索の制限 | <期間・件数・ページ送り・本文取得の可否> |
| 接続担当・アクセス申請先 | <入力> |
| 状態・最終検証日 | <入力> |
| 未対応操作・代替手段 | <例: 許可された資料URLを手動で提供> |

調査用の読み取り権限から開始する。プロンプトに「読み取りのみ」と書くだけでは権限制限にならないため、付与権限と有効なツールを確認する。対象を技術的に限定できない場合は制限を明記し、組織が許可した範囲で利用する。

#### 接続検証

| 確認項目 | 操作・対象 | 結果・確認日 |
| --- | --- | --- |
| 本人・組織の一致 | 接続先の設定または公開ツールで確認 | 未実施 |
| ツール一覧 | 利用可能な操作と書き込み操作の有無を確認 | 未実施 |
| 検索 | 許可済みの既知資料を対象内で検索 | 未実施 |
| 本文取得 | 既知の資料・課題など1件を取得 | 未実施 |
| 出典の再参照 | 元URLから同じ対象を確認 | 未実施 |
| 制限の確認 | スコープ・対象・件数の設定を確認 | 未実施 |

不要な書き込みを実行して権限を試さない。エラーは秘密値を除いた要約と確認先を記録する。検索結果0件、アクセス拒否、未対応、レート制限を区別する。
