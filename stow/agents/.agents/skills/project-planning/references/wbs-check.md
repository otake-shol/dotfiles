# WBS検査の仕様

`scripts/check-wbs.mjs` の判定の正本。スクリプトはこの仕様に合わせ、判定を変えるときは先にこの表とテスト（`scripts/check-wbs.test.mjs`）を更新する。

## 目的

ID・親子・先行関係・日付・稼働日数は答えが一つに決まる。AIが目で数えると見落としや件数の誤りが起きるため、スクリプトで判定し、AIはその結果を読んで影響の説明と修正案を作る。

## 入力

| 形式 | 読み方 |
| --- | --- |
| CSV・TSV | Project Portfolio Sheets（Single版）の「WBS」タブを書き出したもの。見出しの名前で列を探す（列の位置が版によって変わるため） |
| JSON | 生成元の seed（`workItems` 配列）。`start`・`due` は基準開始日・基準終了日の旧名として読む |

- 日付は `YYYY-MM-DD` と `YYYY/M/D` を受け付ける。書き出し時の表示形式の違いで誤判定しないため
- 先行タスクはカンマ・読点・空白で区切ったIDの並びとして読む。生成元のサンプルが `WI-001` のようなIDの単独・列挙のため
- 見つからなかった列は報告し、その列の検査を行わない。列がない状態を「問題なし」と誤認しないため

```bash
node scripts/check-wbs.mjs wbs.csv --holidays holidays.txt   # 人が読む形式
node scripts/check-wbs.mjs wbs.csv --json                     # 機械で扱う形式
```

終了コード: 0 = エラーなし、1 = エラーあり、2 = 入力を読めない。

## エラー（直すまで計画を確定値として扱わない）

| コード | 条件 | 理由 |
| --- | --- | --- |
| `id-empty` / `id-duplicate` | WBS番号が空・重複 | 親子と先行の参照先が一意に決まらない |
| `parent-missing` / `parent-self` | 親WBS番号が存在しない・自分自身 | L2→L1→L0の積み上げが途切れる |
| `parent-cycle` | 親子関係が循環 | 階層と集計が定義できない |
| `pred-missing` / `pred-self` / `pred-cycle` | 先行タスクが存在しない・自分自身・循環 | 着手順が決まらず、日程の根拠にならない |
| `date-format` | 日付として解釈できない | 「来週」などの仮置きを確定日と混同しないため |
| `baseline-order` / `actual-order` | 開始日が終了日より後 | 入力の取り違えで期間が負になる |
| `milestone-span` | 種別「マイルストーン」の基準開始日と基準終了日が別の日 | 節目は1時点。Single版の概要・ガントは同日を前提に◆を表示する |
| `progress-range` | 進捗%が0〜100%の範囲外 | Single版の入力規則と同じ範囲に揃える |
| `schedule-level-inverted` | 上位の階層が下位の配下にある（例: `schedule:L1` が `schedule:L2` の配下） | 全体合意・工程・実行の粒度が逆転する |

## 警告（確認して、意図どおりなら理由を残す）

| コード | 条件 | 理由 |
| --- | --- | --- |
| `schedule-parent-missing` | `schedule:L2` の上位に `schedule:L1` がない（L1に対するL0も同様） | WBSにL0のタグを付けない運用もあるため、エラーにしない |
| `level-mismatch` | 階層が親の階層+1と一致しない | 途中の階層を飛ばした入力の誤りを見つける。既存の分解構造で意図的な場合もある |
| `outside-parent` | 子の基準日程が親の基準日程の範囲外 | 親の期間が古いか、子の割り当て先の誤り |
| `pred-overlap` | 先行の基準終了日が後続の基準開始日より後 | 終了→開始の関係として見た場合の重なり。開始→開始など別の関係を使う案件では正しい場合がある |
| `done-without-actual` | 状態が完了なのに実績終了日が空 | 完了の証拠と実績日程を揃える |
| `actual-start-missing` | 実績終了日があるのに実績開始日が空 | 実績期間が計算できない |
| `duration-mismatch` | 所要日数の値と稼働日数の計算が一致しない | 祝日ファイルの違いか、数式の上書きの可能性 |

## 稼働日数

Single版の所要日数（`MAX(1, NETWORKDAYS(基準開始日, 基準終了日))`）と同じ計算をする。両端の日を含め、土日と祝日ファイルの日付を除き、最小1日。

- 祝日はスクリプトに埋め込まない。年ごとに変わり、組織の休業日も異なるため。`--holidays` に1行1日付のファイルを渡す（`#` 以降はコメント）
- 祝日ファイルを渡さない場合、結果に「祝日未考慮」と表示する。その値を祝日込みの稼働日数として報告しない

## 判定しないこと

- 予測日程: Single版に予測開始・予測終了の専用列がないため。メモ欄の予測は [Sheets雛形への対応](sheets-schedule.md) に従って人が確認する
- クリティカルパスや全体期間の積み上げ: 依存の種類・担当の稼働・休日の扱いが案件ごとに異なり、単純な合計は誤った確約になるため
- 担当者の実在・関係者台帳との照合: WBSの担当者列だけでは関係者全員を表せないため（[スケジュール階層](schedule-levels.md) 参照）
- 書き込み: スクリプトは読み取り専用。正本の修正は SKILL.md の承認手順に従う
