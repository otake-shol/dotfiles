# 既存Sheets雛形へのL1・L2の対応

## 対象の雛形

[project-portfolio-sheets](https://github.com/otake-shol/project-portfolio-sheets)の [単一プロジェクト管理｜公開テンプレート](https://docs.google.com/spreadsheets/d/1CFKVIIpwmEBr49hhlaEwsajoBLPVZlGvLQTtV5fjT3I/edit)を使う。2026-10-10に13タブの構成、WBSの列、概要・ガントの参照数式、入力規則を接続先で確認した。既存の案件シートがあればそちらを優先し、新規案件では公開テンプレートのブック全体をコピーする。

以下の列対応は確認時点のSingle版。旧版の `Single Project Management｜公開テンプレート` とは構成が異なる。実際のブックの見出しを確認し、列位置を決め打ちして書き込まない。

## 入力と表示の役割

| 階層 | 入力元 | スプレッドシートでの表現 | スライドへの展開 |
| --- | --- | --- | --- |
| L0 | WBSの主要成果物・節目、ステークホルダー、憲章 | 概要スケジュールで主要日程を参照。全員の関与は関係者台帳と照合 | 9枚目の全員・節目・受け渡しの1枚絵 |
| L1 | WBSの工程・主要成果物行 | WBSでL1行を抽出し、週次ガントで工程の期間を確認 | 10枚目の工程・依存・判断点 |
| L2 | WBSの詳細作業行 | WBSでL2行を抽出し、日次または週次ガントで詳細を確認 | 11枚目の担当・完了証拠・期限 |

L1・L2を別タブへ手入力して二重管理しない。WBSの既存タグに `schedule:L1` / `schedule:L2` を追加してフィルタビューで抽出する運用を使える。既存のタグは保持し、採用済みの分類があればそちらへ合わせる。ガントは全WBS行を表示するため、全行で見るかブックのフィルタビューで絞り込む。生成数式の展開先へ値を貼り付けない。

`概要スケジュール!A6` は階層1と種別「マイルストーン」を基準開始日の順に最大18件表示する。全L1工程の表示でも全関係者の表示でもない。階層2以下のL1行を載せるために親子関係を崩さず、L1の全件はWBSで確認する。18件を超えた節目も元のWBSとL0台帳で照合する。

## WBSの列対応

| 計画項目 | 既存列 | 入力・利用方法 |
| --- | --- | --- |
| ID・上位との対応 | A WBS番号 / B 親WBS番号 | L1→L0成果物、L2→L1工程を既存IDで接続 |
| 構造・種別 | C 階層 / D 種別 | WBSの深さとスケジュールのL番号を区別。種別は既存の選択肢から指定 |
| 工程・作業名 | E 成果物／作業パッケージ | L1の工程・成果物とL2の実行作業を記載 |
| 状態・優先度・担当 | F 状態 / G 優先度 / H 担当者 | L1の責任者、L2の実行担当。承認者は別途記録 |
| 基準日程 | I 基準開始日 / J 基準終了日 | 合意済みの計画。予測変更だけで上書きしない |
| 実績日程 | K 実績開始日 / L 実績終了日 | 実際の着手・完了日。予測日を入力しない |
| 期間 | M 所要日数 | 既存のNETWORKDAYS数式を保持 |
| 依存・進捗 | N 先行タスク / O 進捗% | 先行IDで接続。進捗の入力範囲は0〜1 |
| 工数 | P 見積工数(h) / Q 実績工数(h) | 葉の作業で計上し、親への重複計上を避ける |
| 節目・完了条件 | R マイルストーン / S 受入基準 | ◆表示にはDの「マイルストーン」が必要。承認・受入条件をSへ記載 |
| 阻害要因・分類 | T 遅延理由 / U タグ | 遅延の原因と対応、L1・L2の抽出用タグ |
| 証拠・補足 | V URL / W メモ | 成果物・レビュー証拠、判断者、外部依存の回答期限 |
| 集計軸 | X 機能 / Y 工程 | 工数分析の既存分類。L1・L2の区分とは別に管理 |

## 親子関係の記入例

下表は空の案件へ適用する構造例。既存のIDをP1・E1・T1へ改名せず、実案件のIDで同じ関係を保つ。日程・担当・工数は実計画から入力する。

| A WBS番号 | B 親WBS番号 | C 階層 | D 種別 | E 名称 | U タグ |
| --- | --- | --- | --- | --- | --- |
| P1 | 空欄 | 1 | 成果物 | 主要成果物 | schedule:L0 |
| E1 | P1 | 2 | 作業パッケージ | 工程・受入可能な成果物 | schedule:L1 |
| T1 | E1 | 3 | タスク | 実行可能な作業 | schedule:L2 |
| M1 | E1 | 3 | マイルストーン | 工程の完了判断 | schedule:L1 |

L1が必ずWBS階層2になるわけではない。既存の分解構造を優先する。マイルストーンの基準開始・終了を同日にし、先行タスク、受入基準、確認者・判断者と証拠を対応づける。関係者のID・氏名・役割は `ステークホルダー` の全員と照合し、担当者列だけでL0の全員を表したことにしない。

## 現在の予測と表示の制約

確認したWBSに予測開始・予測終了の専用列はない。概要の「開始・終了」とガントの「計画」はI・Jの基準日程を参照する。先行タスクを入力しても日程の自動再計算や親工程の自動集約を保証しない。

既存雛形だけで運用する場合はWのメモに `予測開始=YYYY-MM-DD / 予測終了=YYYY-MM-DD / 確認日=YYYY-MM-DD / 理由=…` を記録し、変更判断を `意思決定・変更ログ` へ残す。これは予測バーの自動表示ではない。基準・実績と混同せず、スライドの「予測」欄には確認済みのメモを使う。予測未確認なら「未確認」とし、基準日程を予測と呼ばない。

予測日程の列・ガント表示・親への集約を追加する場合は既存の生成元リポジトリで拡張し、Apps Scriptの非破壊upgrade経路と参照数式を検証する。ブック再構築によるサンプルへの初期化は使わない。

## 更新時の確認項目

- 対象ブックと入力範囲、元データ、数式、入力規則を確認し、案件のWBSだけを更新。
- L1・L2の親IDと先行IDの存在、循環、担当・受入条件を照合。
- WBSの状態・進捗・実績を更新し、概要とガントへの反映を読み戻して確認。
- L2の遅延によるL1工程・L0節目への影響を確認し、基準変更には判断と理由を記録。
- スライドへ要約する際はブックURL、WBS番号、確認日、基準か予測かを発表メモへ記載。

今回確認した公開ブックへの書き込みは未実施。接続ツールに既存ブックのセル更新とブック全体コピーの機能がないため、運用の対応関係を計画スキルへ保存している。
