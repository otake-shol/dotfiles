## 公開動画で確認できる仕組み

- 本人の経験、疑問、音声入力をMarkdownへ変換して企画を開始
- 調査、エビデンス確認、構成、台本、ビジュアル、レビューを工程別に分離
- セリフ、話者、感情、字幕、ビジュアル、BGM、背景、sectionを1枚のJSONで管理
- ClaudeとCodexを工程や動画に応じて使い分け
- 画面を自由生成せず、比較、コード差分、ターミナル、リポジトリカード、グラフ、統計などの型から選択
- 10分動画で30〜40個程度のビジュアルを作成
- 全画面のスクリーンショットを使った、はみ出しと重なりのAIレビュー
- Remotionを使ったコード駆動レンダリング
- TTS音声の長さを基準にscene duration、字幕、口パク、ビジュアル、チャプターを同期
- ZodによるJSON検証と字幕のはみ出し検査
- 背景候補とタイトル候補をAIが作り、サムネイルの最終判断と配置を人間が担当
- 本編のclaimsから縦画面用Shortsを別構成で作成
- 日本語版の人間承認後に翻訳対象文字列だけを9言語へ展開
- 創造的工程と定型工程でモデルを使い分け、トークンと費用を抑制
- 人間の修正とAIレビューをログへ残し、promptやレビュー観点へ反映
- 非公開の自分用学習動画でも制作回数を増やし、改善ループを加速

デザインシステムについて確認できる方針:

- チャンネル固有のカラーパレット、モチーフ、装飾、イラスト規則を定義
- 問い、コード差分、比較、構成図などの再利用可能な型を整備
- 文字量と可読性のトレードオフを画面配置で検証
- 画像生成へ自由度を与えず、輪郭、塗り、色数、カラーコード、キャラクター不変条件で制約
- AI出力をそのまま公開せず、人間の文脈と独自資産を重ねる

## このスキルへの転用

転用した対象:

- 構造化データを正とする制作工程
- 工程別のAIレビューと人間ゲート
- テンプレート選択による品質安定
- マスター台本からの媒体展開
- 修正ログによる継続改善

転用していない対象:

- キャラクター名、外見、関係性、口調
- 配色、モチーフ、装飾、イラスト
- 台本、タイトル、サムネイル、生成プロンプト
- 非公開の実装、学習済みTTS、Web UI

公開動画から分からない部分を事実として補完しない。実装方式はこのスキル利用者の既存環境、予算、権利、運用体制に合わせて選ぶ。
