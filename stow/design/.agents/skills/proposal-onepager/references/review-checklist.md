# レビュー項目

上から順に当てる。指摘は重要な順に並べ、根拠と修正案をセットで出す。
見た目の好みと、読む・判断する妨げになる不具合を分けて書く。

## 1. 価格の表示

- [ ] 取り消し線は、**同じ中身**の**定価**（料金表で決めて、紹介のない相手にも出す価格）からの割引にだけ使っている。「通常価格」は販売の実績がある場合だけ
- [ ] 中身が違う 2 つの価格は、取り消し線ではなく並べて示している（例：今回の内容と、詳細版）
- [ ] 割引は、取り消し線・割引の目印（何の割引か）・割引額の説明の 3 点で示している。目印は 1 か所だけ
- [ ] 料金の枠の中は「今回の内容と価格」だけ。紹介者名などは説明文に回している
- [ ] 「〜から」と書いた下限で、実際に提供できる範囲を明記している（例：業務 1 つの場合）
- [ ] 法的な適合性はこのレビューでは判定しない。気になる表示は専門家に確認する

## 2. 読みやすさ（印刷して手に持つ前提）

- [ ] 本文と注記のサイズが `print-profile.md` の下限以上
- [ ] 説明文を薄い灰色にしていない
- [ ] 1 ページに収まり、フッターが下端にある
- [ ] 1 文字だけ次の行に落ちる折り返しがない

## 3. 情報の構造

- [ ] 同じ内容を 2 回以上言っていない（やることとお渡しするもの、「発注は必須でない」など）
- [ ] 注記が「お願い」と「事務的な条件」に分かれている。1 段落に別々の話題を混ぜていない
- [ ] 番号は時間の順番だけで、1 ページに体系が 1 つ
- [ ] 並列の項目は並列に見える配置（2×2 など）。左右の高さのずれで空白ができていない
- [ ] 読む順番が「位置づけ → やること → 手元に残るもの → 進め方 → 料金 → その後 → 条件」の一本道になっている

## 4. 約束の範囲

- [ ] 聞けるとは限らない情報（作業時間など）を、成果物として約束していない
- [ ] 即時対応・稼働保証など、守れない約束を書いていない（時間や手段の制約は契約時に決める）
- [ ] 時間の上限は「まで」より「目安」と書く方が相手が遠慮しない。上限を超えたときの扱いは契約で決める
- [ ] 法律・税務などの判断は専門家に確認する前提を、事務的な条件に 1 行で書いている

## 5. デザインの規則

- [ ] 書体：見出し＝Zen Maru Gothic、本文＝Noto Sans JP、数字＝Plus Jakarta Sans。`pdffonts` で埋め込みを確認し、代替が出たら報告する
- [ ] 配色：Warm Canvas が主、Deep Navy の面は 1 か所、Accent Orange なし
- [ ] 飾りの記号（見出し前の四角、✓、▶、丸数字）と角丸のカードを、意味なく使っていない
- [ ] `design-intent.md` の「表現選択の見直し」に当たる兆候がない

## 6. 公開範囲

- [ ] 顧客名・金額・紹介者名はプロジェクト側の Markdown にだけあり、このスキルのファイルにない
