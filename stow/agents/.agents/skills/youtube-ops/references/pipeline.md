# 制作パイプライン

## 全体構造

```text
本人の経験・疑問・音声メモ
  -> brief
  -> research + sources + claims
  -> outline
  -> episode.jsonのマスター台本
  -> 台本レビュー
  -> ビジュアル割り当て
  -> 音声・字幕・画面のレンダリング
  -> 長尺パッケージ ─┬─> Shorts
                     ├─> 翻訳版
                     └─> 記事・SNS投稿
  -> 公開
  -> 指標 + 修正ログ
  -> プロンプト・テンプレート・検査規則の改善
```

同じ事実を媒体ごとに書き直さず、`episode.json`のclaimsとマスター台本を派生元にする。派生物を修正した結果、元の意味が変わる場合はマスター台本へ戻して直す。

## 工程別ゲート

### 1. 企画の種

入力:

- 本人が経験、制作、取材、観測したこと
- 一次資料やコミュニティで見つけた変化と疑問
- 視聴者コメントや過去動画の未解決事項

出力:

- 視聴者の課題
- 視聴後に得られる変化
- 本人だから加えられる経験、観測、見解
- 扱わない範囲

人間ゲート`concept`: 誰に何を約束する動画かを承認する。話題性だけで採用しない。

### 2. 調査

調査役がsourcesとclaimsを作り、別のレビュー視点で対応関係を検査する。情報が不足している場合は台本で補完せず、claimを保留または削除する。

出力:

- URL、発行主体、公開日、確認日を持つsources
- `fact`、`observation`、`inference`、`opinion`を区別したclaims
- 競合との差、制約、反例、未確認事項
- 取材、観測、実演の条件と結果

### 3. 構成

セクション名と各セクションの役割を先に決める。セリフを作る前に重複、順序、説明不足を直す。

推奨構造:

1. 視聴理由が分かるコールドオープン
2. 問いまたは困りごとの定義
3. 仕組みや差分の説明
4. 実例、比較、観測、実演
5. 制約、向かない条件、注意点
6. 判断基準または次の一手

人間ゲート`outline`: 動画の約束と構成の一致を承認する。

### 4. マスター台本

セリフ単位で話者、感情、section、visual、sourceを指定する。視聴者役と説明役を置く場合も、固有の関係性と役割を`channel.json`へ定義する。参考チャンネルの口調を転用しない。

AIレビュー:

- claimにない断定
- 出典と発言内容の不一致
- 論理の飛躍と前提不足
- キャラクターと語り口の逸脱
- 冗長な相づちと同内容の言い換え
- 音声で理解しにくい長文、記号、URL

人間ゲート`master_script`: 主張の正確性、本人の見解、自然な言葉を承認する。

### 5. ビジュアル

各セリフへ既存のtemplate IDを割り当てる。新規テンプレートは既存の型で説明できず、今後も再利用できる場合だけ作る。説明型の10分動画で30〜40画面という公開事例を目安にできるが切り替え数を目標化せず、理解の区切りに合わせる。

画面ごとの検査:

- 字幕、写真、図形、分野固有の表示要素のはみ出し
- 要素の重なり
- スマートフォン相当サイズでの可読性
- セリフと画面の意味的な一致
- 引用、ロゴ、スクリーンショットの権利と出典
- 秘密情報、個人情報、通知、タブ名の映り込み

### 6. 音声・レンダリング

レンダラーは固定しない。Remotionなどコード駆動の動画生成を使う場合は音声ファイルの長さから各シーンのdurationと開始位置を計算し、字幕、口パク、ビジュアル、チャプターを同じタイムラインへ同期する。

機械検査:

- `episode.json`のスキーマと参照整合性
- 音声ファイルの存在と長さ
- 映像と音声の総尺
- 字幕の安全領域
- 欠落アセット、未知のtemplate ID、未使用アセット
- チャプター開始時刻の単調増加

### 7. パッケージ

タイトル候補、サムネイル、説明文、チャプター、関連リンクを作る。サムネイル背景と文言は候補を比較し、人間が最終判断する。

人間ゲート`thumbnail`: 小さい表示でも内容と固有名詞が伝わり、過剰な煽りや内容との不一致がないことを承認する。

### 8. 派生

Shortsは本編のclaimsを使い、縦画面用に構成とビジュアルを作り直す。翻訳はマスター台本の承認後に開始し、翻訳対象文字列だけを抽出する。翻訳版から新しい主張を追加しない。

### 9. 公開

人間ゲート`publish`: 最終動画、タイトル、説明文、サムネイル、権利、公開日時を承認する。公開や予約はユーザーが明示的に依頼した場合だけ実行する。

### 10. 計測

公開後の数値と制作中の修正を分離して記録する。次回の変更は仮説として1つずつ試し、複数の変更を同じ結果へ安易に帰属させない。

## 導入順序

最初から多言語と完全自動投稿まで作らない。

1. 主言語のbrief、research、claims、script
2. 長尺版のテンプレートと機械検査
3. サムネイルとShorts
4. 修正ログと週次改善
5. 主言語版が安定した後の翻訳
6. 十分な失敗処理を備えた後の公開補助

人間のレビュー時間が減らない場合は自動化範囲を広げず、修正ログから原因を特定する。
