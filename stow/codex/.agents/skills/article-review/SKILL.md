# 技術記事の編集レビュー

筆者の語調と技術的意味を守りながら、読者への影響がある文章上の問題を指摘する。

## 対象と権限

Markdown、MDX、貼り付けた原稿、URL、明確に特定された記事を受け付ける。既定ではレビューだけを行い、原稿を変更しない。修正を明示的に依頼された場合だけ編集する。

対象を特定できない場合だけ入力を依頼する。技術的主張の正否、API の現在の挙動、コードの再現性を `tech-review` に任せる。

## 文体の復元

次の順で媒体と筆者の文体を確認する。

1. ユーザーの明示的な指定
2. 対象リポジトリの `AGENTS.md`、`CLAUDE.md`、投稿規約
3. `writing-style.md`などの文体資料
4. 同じ媒体の新しい公開記事
5. このスキルの既定チェックリスト

媒体固有の frontmatter、Markdown 拡張、独自構文を通常の文章や壊れた Markdown と誤認しない。古い記事と新しい記事で差がある場合は新しい慣習を優先する。

## 自動校正

対象リポジトリに textlint、markdownlint、独自の文章Lintが設定されている場合は既存コマンドを使う。コマンド、設定、対象範囲を確認してから実行する。

校正ツールや依存関係を無断で追加しない。利用できない場合は手動レビューへ切り替え、未実施と明示する。ツールの指摘をそのまま採用せず、媒体固有構文と筆者の文体に照らして判断する。

## 手動レビュー

[`references/editorial-checklist.md`](references/editorial-checklist.md) を読み、記事全体を確認する。次を区別する。

- `必須`: 誤字脱字、文法的誤り、意味の曖昧さ、構造上の欠落、壊れた表記
- `提案`: 読みやすさや説明順を改善するが筆者の選択も成立する変更

好みだけを誤りとして指摘しない。同じ原因の指摘をまとめ、過剰な言い換えを避ける。記事の良い点を求められない限り独立セクションにしない。

各指摘を次の形式で示す。

```text
[必須] 短い指摘タイトル
Location: path/to/article.md:42
Current: 該当する表現
Suggestion: 具体的な修正案
Reason: 読者への影響または適用した規則
```

指摘がない場合はその旨と、実行できなかった自動校正を報告する。

## 修正の適用

修正を依頼された場合は指摘と対応する変更だけを適用する。frontmatter、コードブロック、リンク、画像、独自構文を維持する。技術的意味、論旨、筆者の意見を変える修正は事前に合意を得る。

編集後は差分と対象リポジトリの文章Lintを確認し、変更箇所、検証結果、残した提案を報告する。
