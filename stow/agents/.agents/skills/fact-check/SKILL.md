# 情報のファクトチェック

検証対象を主張単位に分け、確認できた範囲と残る不確実性を示す。検証の深さを誤判断の影響と利用目的に合わせる。

## 対象と調査範囲

- 対象の文、URL、画像、動画を特定する。複合的な主張を分解し、日時・場所・対象・比較条件を固定する。
- 事実、直接観測、推論、意見・評価を区別する。意見自体の真偽を採点せず、その前提となる事実を検証する。
- 全文を求められた場合は取得できたページや区間を確認する。OCR、画像確認、原典照合の範囲を分けて記録し、一部だけ読んで全体を検証済みにしない。
- 調査だけの依頼で原稿の書き換え、投稿、問い合わせ、削除を実行しない。

## 根拠の確認

1. 元の発信者、発信日時、出来事の日時、原資料への引用経路をたどる。初めて見る発信元はサイト外の情報でも運営主体と専門性を確認する。肩書き、人気、利害関係だけで真偽を決めない。
2. 検索結果やAI回答を手がかりにし、原資料の該当箇所を開く。資料の実在と、資料がその主張を支持することを別々に確認する。公式資料にも適用条件、誤り、当事者としての利害があり得る。
3. 重要な主張は独立した根拠や反証と照合する。同じ発表の転載・孫引きを複数の独立証拠に数えない。都合のよい結論だけを探さず、結論を変え得る証拠も探す。
4. 数値は母集団、標本、期間、分母、単位、比較対象、測定方法を必要な範囲で回収する。相関や観測結果を因果関係に置き換えず、対象外の媒体・集団へ一般化しない。
5. 画像・動画・音声を扱う場合は [視覚・音声資料の検証](references/media-verification.md)を読む。AI検知結果、生成ラベル、来歴情報は内容の真実性と分けて扱う。

重要情報ほど確認を深める。URLを一定数集めることを完了条件にしない。原資料で解決した主張はそこで止める。アクセス不能、資料不足、見解の対立が残る場合は不足点と次に必要な証拠を示して保留する。検索で見つからないことだけで不存在や虚偽を断定しない。

## 判定と報告

各主張に次をまとめる。少数なら短い箇条書き、多数なら表を使う。未実施の検索・逆画像検索・検知を実施済みとして記載しない。

| 項目 | 記録内容 |
|---|---|
| 主張 | 検証対象の文と出現箇所、対象時点 |
| 根拠 | 該当箇所を示すリンク・ページ・タイムコード、原典と転載の関係 |
| 反証・不足情報 | 結論と矛盾する証拠、アクセス制約、未確認の条件 |
| 判定 | 裏付けあり／誤り／文脈不足・誤解を招く／確認不能／意見・評価 |
| 確認日 | 調査日。更新され得る主張には再確認が必要になる条件も記載 |

「裏付けあり」は明示した条件下での判定であり、永続的な真実認定ではない。資料同士が食い違う場合は対象や時点の差を調べ、解消できなければ併記する。証拠のない数値的な確信度を付けない。

共有前の確認を依頼された場合は真偽の判定に加え、受け手が誤解する省略、個人への影響、必要な注記を評価する。確認不能な主張を断定して共有する案は採用しない。公開済みの誤りを扱う場合は訂正内容と影響する派生物を示し、実際の公開変更は依頼された範囲で行う。

## 手順の出典

[出典と試行例](references/sources.md)に書籍の参照箇所と、測定条件を回収した検証例を記載する。書籍の事例・製品仕様・制度を現在の事実として固定せず、個別の検証時に原資料を確認する。
