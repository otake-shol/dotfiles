# デザインの判断基準

スライド制作の手順4〜5（代表の数枚・全体を組む）に入る前に全文読む。
配色・書体・文字サイズ・面の役割は [Standard仕様](../../create-story-slides/references/design-system.md)を正本とする。
OVSのクラスと書き方は [slides-marp.md](slides-marp.md)、根拠は [slides-sources.md](slides-sources.md)。

## 役割からのレイアウト選択

見た目ではなく、そのスライドが伝える役割から型を選ぶ。

| 役割 | 型の例 |
| --- | --- |
| 開始・転換・結論 | 表紙、章の転換、まとめ、転換点 |
| 説明・比較 | 背景、主張＋根拠、比較、原因と結果、Why/What/How |
| プロセス・運用 | 時系列、段階の流れ、二つのレーン、状態付きプロセス |
| 事例・証拠 | 事例、データ、問題と対応 |

- 一枚に一つの型を使う。同じ型を3枚以上続けない。
- 構造が再登場する場合（状態付きプロセスなど）は図の位置とラベルを固定し、変化する状態だけを変える。
- 転換点の型は本当の転換点だけに使う。
- 同じ内容でも時間・比較・因果・手順のどれを伝えるかで型を変える。
- 素材の塊を見栄えのよい型へ流し込み、収まるまで文字や位置を微調整しない。
  型が合わなければ型を選び直すか、スライドを分ける。

## 代表の数枚を先に作る

全体を組む前に、表紙・最も情報が多い1枚・図表の1枚を作って描画を確認する。
型と情報量の組み合わせが破綻しないことをここで確かめてから残りへ広げる。
全体を作った後に共通の問題が見つかると、全ページの作り直しになる。

## 情報量とリズム

- 3秒見て目をそらし、そのスライドの要点を言えるかで判断する。言えなければ情報を削るか分割する。
- 発表モードの本文は聞きながら読める量（目安140字）に収める。配布モードは読むだけで理解できる量まで許容する（目安420字）。
- 収まらないときは文字を縮める前に「削る・図にする・2枚に分ける・ノートへ移す」の順で検討する。
- 密なスライドの後には一つの主張だけの余白の多いスライドを置き、緩急をつける。
  すべてのスライドが同じ密度だと、どれも印象に残らない。
- 複雑な図や手順は段階に分けて見せる。HTMLで発表するなら箇条書きの段階表示（[slides-marp.md](slides-marp.md)）も使える。

## 章の現在地表示

3〜6個の安定したフェーズがあり、同じ章が3枚以上続く場合だけ、ページ上部に章の現在地を示す。
ラベル・順序・位置・大きさは固定し、変えるのは現在の章（Active）一か所だけにする。
Activeは色だけでなく太字と下線でも示し、通常の進行に強調色を使わない。
OVSテーマではMarpの `_header` に章名を並べ、現在の章だけを `**太字**` にする（太字と下線はテーマが付ける）。

```markdown
<!-- _header: '背景　｜　**変更内容**　｜　検証と次の一手' -->
```

## 関係性と読む順番

以下は「伝わるデザイン」の考え方をMarkdownスライドへ適用した制作指針。
サイトの数値目安やPowerPoint向け操作をそのままCSSの固定値にせず、
ユーザーのテンプレート、発表・配布の用途、実際の表示サイズに合わせて判断する。

- 見出しと説明、図とその解説を一組として配置する。組の中の間隔より組同士の間隔を広くする。
  比較では左右の項目順と見出し位置を揃え、手順では進む方向を統一する。
- 本文や図の開始位置を揃える。同じ役割の見出し・説明の位置はスライド間でも揃える。
  内容の関係が変われば配置を変え、見た目の変化だけを目的にレイアウトを増やさない。
- 読む順番が曖昧な場合は配置を整理する。順番に意味がある場合だけ番号や矢印を補う。
  空いた場所を埋めるために、別の項目の説明を置かない。

根拠：[レイアウト](https://tsutawarudesign.com/miyasuku4.html)。

## 重要度と余白

- 最初に見てほしい主張を決め、見出し、根拠、補足の順に強弱をつける。
  同格の情報は同じ扱いにし、すべてを太字・大文字・強調色にしない。
- 図表では比較してほしい行・列・系列を選び、必要なラベルや注釈で注目箇所を示す。
  比較条件や反証となる値を消して結論を強調しない。単位と期間も残す。
- 文字と枠、図と説明の間にゆとりを残す。囲いはグループや境界を示すために使い、
  囲う必要がなければ通常レイアウトと余白で整理する。
  表の罫線や装飾が内容より目立つ場合は対応関係を保ったまま控えめにする。
- 消しても意味が変わらない要素（飾りの図形、繰り返しのロゴ、意味のない色面）は消す。
  伝えたい信号に対する雑音を減らすほど、残した要素が効く。

根拠：[レイアウト](https://tsutawarudesign.com/miyasuku4.html)、
[表とグラフ](https://tsutawarudesign.com/miyasuku1.html)。

## 日本語の行と改行

- 複数行の説明は左揃えを基本にする。中央揃えは表紙や短い独立したメッセージなど
  読み始める位置を探す負担が小さい場面で使う。
- 述語だけが次行に残る折り返しや、語句・数値と単位を分断する改行を避ける。
  先に文章と列幅を調整し、必要なら意味のまとまりで改行する。改行後も事実と条件を保つ。
- 並列する項目は見出しと説明の役割を揃える。
  例えば「SVG・PNG・altを同時生成」の末尾だけが折り返されるなら、
  見出しを「素材の一括生成」、説明を「SVG・PNG・alt」に分ける方法がある。
- 長い行を画面いっぱいに広げたり、細い列で細切れにしたりしない。
  行高はフォント・行長・行数に合わせる。サイトにある行間の目安を
  CSSの `line-height` の値として機械的に転記しない。
- OVSテーマは見出しと本文を文節で折り返す（`word-break: auto-phrase`）。
  この機能は `lang: ja` のときだけ働くため、front matterに必ず書く。
  それでも1〜2文字だけが最終行に残る箇所は `ovs deck check` が知らせるので、語の選び方か列幅で直す。

根拠：[文字組み](https://tsutawarudesign.com/yomiyasuku4.html)。

## 色の意味と識別手段

- 対象・状態・強調のどれを色で表すかを決め、資料全体で同じ意味に同じ色を使う。
  意味の違いを示す必要がない箇所では色を増やさない。
- 状態や系列は文字ラベル、形、線種などでも区別する。
  例えば完了・未完了を色だけで示さず、状態名を添える。
- 色は値だけでなく面積と役割まで固定する。資料全体の面積は背景・白が大半（目安6〜7割）、
  主色が2割弱、濃色が1割弱、淡色が数%、強調色は2%程度にとどめる。
  「面積は静かに、主色で構造をつくり、強調色は本当の例外だけに使う」。
- 強調色（OVSではオレンジ系）は緊張・例外・変化・行動だけに使う。
  背景とのコントラストが本文基準に届かない強調色は本文色にせず、線・境界・淡い背景との組み合わせに限定する。
- 彩度の高い色や強調色を広い面積に重ねない。落ち着いた背景を選びつつ、
  本文や注釈まで薄くして読みにくくしない。OVSでは既存トークンとクラスを使う。
  必要な表現が未実装ならテーマ変更の課題として扱い、スライド内に独自配色を増やさない。

根拠：[配色](https://tsutawarudesign.com/miyasuku5.html)、
[配色のバリアフリー](https://tsutawarudesign.com/universal1.html)。

## 図表

チャートの形はデータで答えたい問いから選ぶ。OVSで作れる形（`ovs list charts`）との対応は次のとおり。

| 答えたい問い | 関係 | OVSのチャート |
| --- | --- | --- |
| 項目間の大きさはどう違うか | 大きさ | `bar`、`dot` |
| 順位はどうか | 順位 | `bar`（並べ替え） |
| 時間とともにどう変わるか | 時間変化 | `line`、`slope`（2時点）、`small-multiples` |
| 全体の内訳はどうか | 部分と全体 | `stacked-bar`、`waterfall`（増減の寄与） |
| 基準や目標からどれだけ外れるか | 偏差 | `waterfall`、`progress` |
| 2つの変数に関係があるか | 相関 | `scatter` |
| 2つの分類の組み合わせはどうか | 分布 | `heatmap` |

- タイトルにはグラフから読み取ってほしい結論を書く（例: 「6月に899コミットのピーク」）。グラフの種類名を書かない。
- 見てほしい系列・期間を一つだけ強調し、他は控えめな色にする。凡例を置かず、線や棒の近くに直接ラベルを付ける。
  説明の文字は対応する部分のすぐ近くに置く。離れた凡例やキャプションと見比べさせない。
- 1枚に1グラフを基本にする。比較が主題なら同じ軸の小さなグラフを並べる（`small-multiples`）。
- 棒・積み上げ・progressは0起点。系列は4つまで。疑似データや3D、円グラフの多用を避ける。
- 実データは `ovs chart` で生成し、インラインSVGを手書きしない。単位・期間・出典を図とフッターに残す。
- 相関を示すと因果と受け取られやすい。因果を主張しない場合はタイトルと注記で区別する。

## 素材の見せ方

主張の理解に必要な部分だけを見せる。

- 図解: 線・平面・少ない色で構成し、判断箇所を濃色、例外だけを強調色にする。
- グラフ: 一つの系列・変化点を強調し、凡例や罫線を減らして要点をタイトルへ置く。
- スクリーンショット: 全画面を縮小せず、決定的な領域を切り出して拡大し、注釈は一つだけにする。
  実物の画面は真正性そのものが証拠になる場合だけ使う。
- 画像・イラスト: 余白を残し、本文と競合させない。生成画像に文字を入れず、同じ画像を使い回さない。
  画像と文を並べるならMarpの背景分割（[slides-marp.md](slides-marp.md)）を使い、HTMLで配置を組まない。

## アクセシビリティ

- 文字の大きさ: 本文18〜22pt、補助ラベル16pt、出典・ページ番号10〜13ptを使う。
  `ovs deck check` の警告下限は安全網であり、デザイン上の推奨サイズではない。
- コントラスト: 本文は背景と4.5:1以上、大きな文字（24px以上、または太字18.5px以上）は3:1以上にする。
  濃色背景のスライドでは注釈やフッターの色まで確認する。
- 色だけに頼らない: 状態・系列・強調はラベル・形・線種・位置でも区別する。
- 代替テキスト: 内容を持つ画像と図には結論が分かるaltを付ける。背景の装飾画像には不要。
- 言語: front matterの `lang: ja` で読み上げと改行を日本語として扱わせる。
- 動き: 点滅や速い動きを使わない。段階表示は内容の順序を示すためだけに使う。

`ovs deck check` は文字の大きさ・コントラスト・言語指定を実測して知らせる。

## AI生成で起きやすい失敗

AIで作った資料に繰り返し現れる失敗。代表の数枚を作った段階と全体を組んだ後に見直す。

- 全スライドが「見出し＋箇条書き」の同じ構造で並ぶ。役割に合う型（表・時系列・図・数値）を選ぶ。
- 何でも枠やカードで囲む。囲いはグループや境界を示すときだけに使い、数値は数値、引用は大きな文字で見せる。
- 消しても困らない飾り（意味のない図形・アイコン・色面）を足す。
- すべての項目を太字・強調色にして、何が重要か分からなくなる。
- 文字の大きさの差が小さく、見出しが本文に埋もれる。
- 余白がどこも同じになり、関係の近さが配置から読み取れない。
- 素材の文章をほぼそのまま貼り、スライドが文書になる。編集で削ることが仕事の中心。
- 収まらない内容を縮小や `fit` で押し込む。分割か削減で直す。

配色と装飾はスライド作成スキルのStandard仕様に統一する（2026-10-09 ユーザー判断）。
旧OVSの見出し下の短い線、太い輪郭、オフセットシャドウ、多色の装飾は追加しない。
通常の表紙はPrimary Blue、本文ページはWarm Canvas、結論はDeep Navyを使う。
