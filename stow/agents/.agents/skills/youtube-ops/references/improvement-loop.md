# 改善ループ

## 記録の分離

次の3種類を混ぜない。

- 制作修正: 人間がどこを何に直したか
- レビュー指摘: AIまたは人間が何を問題と判断したか
- 公開後指標: 視聴者の行動として何が起きたか

指標が良かっただけで制作上の修正を正解と断定しない。指標が悪かっただけで内容を誤りと断定しない。

## 修正ログ

人間が台本、タイトル、説明文、ビジュアル、サムネイルを直したときに`logs/corrections.jsonl`へ残す。理由を「なんとなく」ではなく、対象不明、根拠不足、口調逸脱、文字量超過など再利用できるcategoryで記録する。

同種の修正が繰り返された場合は原因に近い層へ反映する。

| 原因 | 反映先 |
|---|---|
| 入力文脈の不足 | `channel.json`またはbrief |
| 生成判断の偏り | prompt |
| 表現の選択肢不足 | visual templateまたは構成パターン |
| 機械判定できる違反 | validator |
| 単発の好み | 昇格せずログだけ保持 |

昇格後は`promoted_to`へ変更先を記録し、次回の制作で同じ修正が減ったか確認する。

## 公開後指標

取得可能な範囲で次を同じ経過時点にそろえる。

- インプレッションとクリック率
- 冒頭30秒の維持率
- 平均視聴時間と平均再生率
- 総再生時間
- 登録者増減
- 流入元
- コメントで繰り返された疑問
- Shortsから本編への遷移を示す指標

24時間、7日、28日などチャンネル内で同じ窓を使う。規模の異なる動画を再生数だけで比較しない。

## 定期レビュー

週次:

1. correction categoryの頻度確認
2. 重大な事実誤認と権利問題の即時修正
3. 次の1〜3本で試す仮説を一つ選択
4. prompt、template、validatorの変更
5. 変更理由と戻し方の記録

月次:

1. テーマの柱ごとの制作費と視聴者価値
2. 冒頭、構成、ビジュアル型、タイトル型の傾向
3. 使われないテンプレートと不足するテンプレート
4. 人間レビュー時間の推移
5. 自動化を広げる工程と人間判断を残す工程

人間レビュー時間が増えた場合はモデルを強くする前に、入力不足、型不足、検査漏れを確認する。
