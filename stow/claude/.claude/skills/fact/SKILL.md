# fact — 小さな事実の記録

**判断・解釈・構造化をしない**記録専用スキル。`life-consult` から「判定」を抜いた軽量版。
入力 → 仕分け → 追記 → コミットまでで終わる。**助言も分析も返さない。**

## なぜ日次ノートでないのか（作る前の実測・2026-08-16）

| 経路 | 状態 |
|---|---|
| `daily-log` スキル + `00_daily/` | 🔴 全 9 ファイル・最終 2026-04-16 ＝ **4 ヶ月ゼロ** |
| `20_areas/life-plan/daily/` | 🔴 空 |
| `capture` + `00_inbox/` | 🟡 人間の投入はほぼゼロ（自動生成が大半） |
| **テーマ別の正ファイルへの追記** | 🟢 活発（`health-log` だけで 2026-08 に 5 コミット） |

**死んだのは「日次ノート」という形式**であって記録習慣ではない。生きているのは「Claude Code から既存ファイルへ追記」の経路。
落ちているのは**判断を伴わない事実**——相談の形にならないので `life-consult` の入口に乗らない。

⚠️ `sleep-rules` §0（装着率 41%・転記 3 ヶ月 0 件で計測を廃止）と同型の失敗を **3 回目にしない**。
そのための設計制約が下の「絶対にやらないこと」。

### daily-log の死因（2026-08-16・本人の指摘を受け SKILL.md 本体を精査した結果）

> 「daily-log があるなら再運用でよいのでは」への回答。**推測でなく artifact に書いてあった。**

| `daily-log` の仕様 | 起きること |
|---|---|
| 前日の未完タスク `- [ ]` を当日へ転記 | 毎朝**未達リストが自動で目の前に来る**＝減点型の自己審理には毎日の判決文 |
| 「**空白＝第一級シグナル**」で追及（「直近 3 日で称賛/差分が空欄ならその場で 1 件ずつ聞き出す」「『書くほどのことがない』という返答自体を値引き作動の兆候として扱う」） | **書いても書かなくても審理される**＝逃げ場がない |
| 3 モード（朝/随時/夜）＋ wrap の通読・整形・翌日申し送り | 起動判断と儀式のコスト |

- ⚠️ **これらは善意で入っている**（`08_strengths-shadows` 4-3 外部検知機構として、判決の文法に対抗するための設計）。**善意のベクトルの実例**——善意が付いた設計ほど条件を確かめずに受けやすい
- **インポスター検知は既に別経路で生きている**：クラウドジョブが毎週土曜に `00_inbox/impostor-check-YYYY-MM-DD.md` を push（2026-08-15 実行済み）。**daily に持たせる理由は消えている**
- **回収する資産はほぼ無い**：セクション判定は本スキルの 2 分類で足り、**Evergreen 候補の検出・切り出し提案は「痛み→構造化」の加速器なので意図的に入れない**
- **残る本質的な差は 1 点＝日次 1 ファイル vs 月次 1 ファイル**。日次はファイル一覧で「今日の分が無い」が可視化される。**空白が見えない方がこの人には合う**——これだけが本物の設計差
- **`daily-log` は削除しない**。status を落として **2026-09-27 の凍結解除判断**へ回す（`/fact` が実際に動いたかの実測で決める。`sleep-rules` §0 が実績で判定した前例と同じ作法）
- 🧠 **手順上の反省**：本スキルは死因を確認する前に作られた。artifact を読んだ結果として結論は変わらなかったが、**確かめてから作るのが正しい順序**だった

## 使い方

- `/fact 〈一行〉` — 追記してコミットまで
- `/fact 〈複数行〉` — まとめて渡してよい
- `/fact`（引数なし）— 当月ファイルを表示するだけ
- 会話の中で事実が出たときに、本人が「記録しておいて」と言った場合も同じ動作でよい

## 追記先

`$HOME/Library/Mobile Documents/iCloud~md~obsidian/Documents/obsidian/00_inbox/facts/YYYY-MM.md`（当月・なければ作成）

新規作成時のテンプレート:

```markdown
---
type: log
status: active
tags: [log, primary-source]
created: YYYY-MM-01
updated: YYYY-MM-DD
---

# 一次情報ログ YYYY-MM

> 判断・解釈を加えず溜める場所。正ファイルへの昇格はゲートで行う（このファイル自体は判断に使わない）。
> ⚠️ `capture` の振り分け対象外。月次で PARA へ移動させない。

## 事実

## 気づき
```

## 仕分けの唯一のルール

入力を **2 つのどちらか**に置くだけ。これは判定ではなく置き場の選択。

| セクション | 入るもの | 例 |
|---|---|---|
| **## 事実** | 誰が何を言ったか・何が起きたか・何時間かかったか（**行動レベルの証拠**） | 「1on1 で『横展開は来期以降』と言われた」「MVP の実装に 6h」 |
| **## 気づき** | 解釈・違和感・感情（**本人の読み**） | 「来期の話が出たとき、身構えた」 |

- **物理的に分ける理由**：Vault の原則「**事実（行動レベルの証拠）を言葉（解釈）より重く扱う**」の実装。混ぜると、後から読むとき解釈が事実として効いてしまう
- 迷ったら **## 気づき** へ（事実欄の純度を優先する）

行の形式は `- MM-DD 〈本人の言葉のまま〉`。時刻は書かない（粒度を細かくすると儀式になる）。

## 絶対にやらないこと

| 禁止 | 根拠 |
|---|---|
| **要約・整形・言い換え** | 本人の言葉のまま入れる。整形した瞬間に解釈が混入する |
| **判定・評価・助言・分析を返す** | 判定が要るなら `/life-consult` を使う。このスキルは通すだけ |
| **連続日数・件数・達成率・グラフを出す** | telic 化＝審理の再開。**空白の日を「サボり」にしない**（免罪符ルール） |
| **数値計測の復活** | `sleep-rules` §0 で廃止済み。体調は §1 の観測語彙のまま書く（早朝覚醒・朝の重さ・妻の指摘） |
| **火曜日の夜に関する記録** | `north-star` 恒久ルール。**気づくのは可、記録は不可**。気づいたら書かずに妻に言う |
| **妊活・医療の中身** | `family-event-index` §3/§4。試行状況・周期・判明時期の予測を書かない |
| **新規ノートの作成** | 月次ファイル以外は作らない。凍結中（〜2026-09-27） |
| **新しいモデル・フレーム・名称の導入** | 同上。名前を付けたくなったら既存語彙（署名・開廷モデル・三層モデル・スペックシート）で言い換える |
| **リマインド・催促** | 書かない日があってよい設計。促した瞬間に儀式になる |

## 昇格（溜め置き → 正ファイル）

**このスキルは昇格をしない。** 既存ゲートのときに `life-consult` 側でまとめて行う。

| ゲート | 昇格先 |
|---|---|
| 2026-09-27 四半期レビュー | 各正ファイル（凍結解除判断と同時） |
| 2026-10-18 90 日計画レビュー | `10_projects/おたけ屋/鹿児島副業案件獲得-90日計画-2026.md` |
| 2026-12 末 方向決断（二値） | `current-role-transition-decision-2026-07-19.md` ほか |

昇格しなかった行は消さずに残す。**溜め置きは進捗表ではないので、未昇格が滞留ではない。**

## 手順

1. 当月ファイルの有無を確認（なければテンプレートで作成）
2. 入力を `## 事実` / `## 気づき` のどちらかへ追記（本人の言葉のまま）
3. frontmatter の `updated` を当日に更新
4. コミット → `git pull --rebase origin main` → `git push`
   - メッセージ例: `docs(log): 一次情報を追記（2026-08-17）`
   - `Co-Authored-By` 行は `~/.claude/CLAUDE.md` の規約に従う
5. **追記した行をそのまま 1 行で返して終わる。** 感想・要約・次のアクション提案を付けない

## rebase が止まったら

`unstaged changes` で止まったら NFD/NFC 重複を疑う。`git rebase --abort` で復旧 → NFD 側を `git rm --cached`。
詳細は Vault ルート `CLAUDE.md`「バックアップ運用」節。
