# 公開前チェックリスト

## 構成

- [ ] 導入だけで対象読者、課題、到達点を判断できる
- [ ] 見出しの順序が読者の疑問または作業手順に沿っている
- [ ] 背景説明が実装や結論より長くなりすぎていない
- [ ] 各節に読む理由があり、前後のつながりがある
- [ ] まとめが本文の結論を過不足なく再掲している
- [ ] 参考資料に一次情報が含まれている

## 技術的信頼性

- [ ] 中心的な主張に一次情報または検証結果がある
- [ ] 仕様、実装の挙動、観測結果、推測、意見を区別している
- [ ] コードを新しい環境で再現できる
- [ ] import、依存関係、環境変数、作成ファイル、起動手順を必要な範囲で示している
- [ ] 対象バージョン、検証環境、確認日を記録している
- [ ] 実験的な仕様に安定度、対応状況、フォールバックがある
- [ ] コードと記事中の説明が一致している
- [ ] 構文確認と実行時の確認を区別している

## 安全性と利用条件

- [ ] 認証情報や個人情報をサンプルへ含めていない
- [ ] 破壊的操作や本番操作の影響と安全な試し方を示している
- [ ] セキュリティとプライバシーへの影響を確認している
- [ ] アクセシビリティへの影響を確認している
- [ ] ブラウザ、OS、ランタイム、ライブラリの互換性を確認している
- [ ] 未対応、未確認、失敗条件を区別している

## 文章と表記

- [ ] 媒体が求める文体へ統一している
- [ ] 同じ概念を同じ用語と公式表記で示している
- [ ] 一文に複数の論点を詰め込んでいない
- [ ] 指示語の対象が明確である
- [ ] 強い断定の根拠を主張の近くに置いている
- [ ] コードと画像の前後に目的と観察結果がある
- [ ] 概要だけで記事の内容と結論を判断できる
- [ ] リンク切れと参照先の内容を確認している

## 学習体験

- [ ] 最小例から実践例へ無理なく進める
- [ ] 読者が途中結果を確認できる
- [ ] 重要な手順を注記の中へ隠していない
- [ ] 読者が持ち帰る結論を具体的な命題で示している
- [ ] 理解度チェックを使う場合、記事の中心概念を問う
- [ ] 理解度チェックの正答が一意で誤答にも説明がある

## 最終報告

次を簡潔に報告する。

1. 変更または主な指摘
2. 実行した検証と結果
3. 未実施または未確認の重要事項
4. 公開可否を左右する残課題
