# プロジェクト計画スライドの雛形

自己紹介: compact（R3: 発表者未定の再利用用テンプレート）
「自己紹介を入れて」で紹介スライドを追加でき、「名前も不要」で表紙と終わりの発表者欄を削除できる。

`project-planning` で計画内容を整理し、`create-story-slides` の計画モード・Standardテーマで関係者へ説明するための18枚の雛形。14枚の内容に進め方の説明1枚と章区切り3枚を加えた構成。
[deck.md](deck.md)を対象プロジェクトへコピーして使う。固有の案件・人物・実績を含めず、全入力欄を `［…］` で示す。入力欄を残したPDFは雛形のプレビュー。

## 想定用途

キックオフ、計画レビュー、実行条件の合意形成。新規案件を前提に過去の振り返りを必須にしない。継続案件では現状の前に前期間の結果を追加できる。承認依頼に絞る場合は目的と最終判断を保ちながら圧縮する。

N01の固定順序: `purpose` = 目的と範囲 → `execution` = 実行の設計 → `governance` = 判断と運用。状態は現在位置のみで、計画や工程の完了を意味しない。
素材はすべてこの雛形の編集可能な図と入力欄。外部画像・ロゴ・測定値は使用しない。L0の図は配置例で、同じ幅の列に同じ長さの期間を設定し、バーの開始・終了・依存関係を実計画へ合わせる。L1・L2のIDも記入例で、利用時は正本のIDを維持する。

## L0・L1・L2の使い分け

[スケジュール階層の共通ガイド](../../stow/agents/.agents/skills/project-planning/references/schedule-levels.md)に、階層の定義、管理項目、正本・更新担当、変更の連動をまとめている。

| 階層 | 読者・目的 | この雛形での表現 |
| --- | --- | --- |
| L0 | スポンサー・関係者による全体の合意 | 9枚目。全員の行、関与期間、成果物の受け渡し、主要マイルストーンを1枚で表示 |
| L1 | PM・チーム責任者による工程管理 | 10枚目。工程・成果物の完了条件、予測期間、責任者、先行ID、判断点 |
| L2 | 担当者による日々の実行 | 11枚目。代表作業の担当、完了証拠、予測期限、先行ID |

L0のP1・P2 → L1のE1・E2 → L2のT1〜T3を親IDでつなぐ記入例を載せている。L2の実績・予測・阻害要因をL1で確認し、主要期限や成果に影響する場合はL0の判断へつなぐ。L0で決まった変更はL1・L2へ反映する。

L1・L2の全件と基準日程・現在の予測・実績は各案件の正本で管理する。スライドでは説明に必要な範囲を要約する。L0・L1・L2はこのツール群の運用上の定義で、PMBOKで指定された帳票名として扱わない。

Sheetsを使う場合は [既存Single版への列対応](../../stow/agents/.agents/skills/project-planning/references/sheets-schedule.md)に従い、WBSのL1工程・L2作業から10・11枚目を作る。公開雛形の概要・ガントは基準日程を表示するため、この原稿の予測欄へそのまま転記しない。予測はWBSのメモなど確認した情報から取り出し、未確認なら明記する。

L0は意思決定者・PM・利用部門・実行担当・確認担当・運用担当の6行と、開始・要件合意・設計合意・成果物完成・受入・公開の6つの節目を配置例にしている。実際の関係者名と節目へ置き換え、必要な行・節目を追加する。役割名だけで全員を表したことにせず、関係者台帳の全員を照合する。菱形は各人の参加・判断、矢印は受け渡しを表し、最終承認者は台帳で明示する。

L0の単独SVGをPNGへ描画して目視確認済み。静的検査では9枚目の情報量警告が1件残る。全関係者と主要マイルストーンを同じ図に示す依頼に対応するため保持し、文字を縮小して警告を避けない。スライド全体の描画検査は下記のChrome起動制限で未完了。

L0の依存矢印に経路Dを採用。菱形の右側から水平に伸ばし、工程中の確認点を表す白丸の真上で垂直に下ろす。太い青線・大きな先端・背景色の縁取りでマイルストーンの破線と区別する。白丸の名称・時期・成立条件を正本で指定し、工程全体の開始条件とは区別する。スライドでは経路Dと同じ接続規則を既存の図の寸法へ合わせている。修正後のSVG構文検査、単独PNGの目視、HTML・発表メモの再生成を確認済み。

## 入力と正本

1. 対象プロジェクトの計画の正本を指定する。既存の計画書、Planbase JSON、Sheets、GitHubのIssue・Projectを優先する。未作成なら [計画書の雛形](../../stow/agents/.agents/skills/project-planning/references/project-plan.md)を使える。
2. `deck.md` を非公開情報の取り扱いに合う案件内の保存先へコピーする。入力済みの資料を共通テンプレートへ戻さない。
3. `［…］` を実計画の情報に置換する。未決の担当・期限は「未定」とし、17枚目に確定に必要な判断を残す。
4. 4枚目の正本名・版・確認日を更新する。各ページの発表メモには必要に応じて資料名、作業ID、出典を追加する。
5. 発表者名と役割を表紙・終わりに入力する。既知のチーム内向けなど紹介が不要な場合は両方の `.compact` 行を削除する。
6. 正本へ変更を反映してから要約を更新する。日付・金額・担当・完了条件・依存関係の不一致を確認し、描画を再検証する。

入力欄の分類: プロジェクト名・成果・期間、課題と根拠、完了条件と確認者、範囲と優先理由、工程と予定時期、判断条件、先行作業と回答期限、担当と権限、体制と費用、リスク、正本と版・確認日、次の行動、発表者名・役割。

## 書き出しと検証

dotfilesのルートから実行する。テーマの実体を複製せず、既存のスライドスキルを参照する。

```bash
bash stow/design/.agents/skills/create-story-slides/scripts/build.sh \
  templates/project-plan-slides/deck.md output/slides/project-plan-template
```

配置済みのスキルを使う場合:

```bash
bash ~/.agents/skills/create-story-slides/scripts/build.sh \
  path/to/deck.md path/to/preview
```

PDF、発表メモ、各ページPNG、コンタクトシートが生成される。発表メモはPDFに埋め込まない。`marp` とChrome系ブラウザを利用し、`ovs` があれば描画の実測検査も行う。入力後は全ページを確認する。雛形の入力欄は意図した内容で、完成資料では未決表示以外を置換する。

HTMLと発表メモだけを書き出す場合:

```bash
marp --no-stdin --html --allow-local-files \
  --theme stow/design/.agents/skills/create-story-slides/assets/story-slides.css \
  templates/project-plan-slides/deck.md -o output/slides/project-plan-template/deck.html
marp --no-stdin --notes templates/project-plan-slides/deck.md \
  -o output/slides/project-plan-template/deck.notes.txt
```

2026-10-09の制作時にHTML・発表メモの生成を確認。2026-10-10にL0・L1・L2の構成を反映。PDF・スライドPNGの生成は実行環境の権限制限でChromeが起動できず未完了。スライドの描画の実測と目視も未実施。通常のローカル環境で上のビルド手順を実行して確認する。

## 利用プロンプト

```text
$project-planning 対象プロジェクトの計画の正本を読み、
dotfilesの templates/project-plan-slides/deck.md を雛形として
キックオフ用の計画スライドを作って。
create-story-slidesの制作・描画検証を使い、正本への参照を残して。
未決事項は確定した約束に書き換えず、今回必要な判断を示して。
```
