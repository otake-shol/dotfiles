# Markdownスライド制作の共通指針

Claude `/slides` とCodex `source-command-slides` の共通仕様。
構成・デザイン・出力・検証の変更はこのファイルと同じ階層の `slides-*.md` に集約する。
このファイルを最初に全文読み、各工程の参照先をその工程に入る前に全文読む。

## 目指す状態

聞き手が自分の次の行動を迷わず受け取れる資料。
タイトル列だけで主張と因果が追え、各スライドは3秒で要点が分かる。
表示・出典・時間を機械と目視の両方で検証してから渡す。

## 進め方

次のチェックリストを回答にコピーし、進捗を更新しながら進める。

```text
スライド制作:
- [ ] 1. 受け取る: 5項目とモード（発表・配布）を確定する → slides-story.md
- [ ] 2. 核を決める: 中心メッセージを一文にし、3分で話せる筋にする → slides-story.md
- [ ] 3. 骨組み: 用途の型でタイトル列を作り、ovs deck outline で横の論理を確かめる → slides-story.md
- [ ] 4. 代表の数枚: 表紙・最も密な1枚・図表の1枚を先に作り、見た目を確定する → slides-design.md, slides-marp.md
- [ ] 5. 全体を組む: 1枚に1役割・1主張・1型。証拠は図表、詳細はノートへ → slides-design.md, slides-marp.md
- [ ] 6. 機械検査: ovs deck verify を error 0 にする → slides-review.md
- [ ] 7. 目視検査: 枠付き画像と25%一覧でリリースブロッカーを潰す → slides-review.md
- [ ] 8. 発表準備: ノートを台本にし、推定時間を持ち時間の9割に収める → slides-review.md
- [ ] 9. 報告: 成果物・実施した検証・未確認の項目を伝える → slides-review.md
```

材料が十分なら手順2〜3の結果（中心メッセージとタイトル列）を短く示して制作を続ける。
ユーザーが構成確認を求めた場合だけ手順3で止める。

## 原則

迷ったらここへ戻る。根拠と出典は `slides-sources.md`。

1. 相手の次の行動から逆算する。素材の要約から作り始めない。
2. 中心メッセージを一文で言えるまで作り始めない。関係しないスライドは削る。
3. タイトルは話題名ではなく主張にする。タイトル列だけで話が通る状態にする（横の論理）。
4. 本文にはタイトルの証拠だけを置く（縦の論理）。証拠は図・表・数値を優先し、箇条書きに逃げない。
5. 1枚1メッセージ。3秒で要点が伝わらなければ分割する。枚数を増やす方が詰め込むより安い。
6. 話す文章をそのまま映さない。画面は短い語と証拠、文章はノートへ。
7. 数値には単位・期間・比較対象・出典を付ける。測れていない効果は主張しない。
8. 型は見た目ではなく役割で選ぶ。同じ型の3連続、装飾のための装飾、何でも枠で囲む表現を避ける。
9. 色は意味に結び付け、強調色は例外の一か所だけに使う。色以外の手掛かりも添える。
10. 冒頭30秒で「なぜ聞くか」を示し、最後は持ち帰る一文と次の行動で終える。
11. 完成の判定は機械検査と目視の両方。変換成功やlint成功だけで合格にしない。
12. 発表後に反応と時間を記録し、次の資料と指針を直す。

## 検査コマンド

```bash
ovs deck outline slide.md --minutes 10              # タイトル列と推定時間
ovs deck verify slide.md --minutes 10 --shots DIR   # 静的検査（lint）と描画の実測（check）
ovs deck rules                                      # 検査ルールと根拠
```

`ovs` がなければ `node "${XDG_CONFIG_HOME:-$HOME/.config}/otake/visual-system/scripts/ovs.mjs"` で実行する。
dotfiles内で未インストールの内容を検証するときは `stow/design/.config/otake/visual-system/scripts/ovs.mjs` を使う。
