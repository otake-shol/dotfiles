# 検証・発表準備・改善

スライド制作の手順6〜9（機械検査・目視検査・発表準備・報告）に入る前に全文読む。

## 目次

- 機械検査
- 目視検査
- リリースブロッカー
- 採点表
- 発表準備
- 報告
- 発表後の改善

## 機械検査

```bash
ovs deck outline slide.md --minutes 10
ovs deck verify slide.md --minutes 10 --shots "${TMPDIR:-/tmp}/slides-check"
```

配布モードの資料は `--mode read` を付ける。`verify` は次の2つを続けて実行する。

| 検査 | 内容 | 主なルール |
| --- | --- | --- |
| `ovs deck lint`（静的） | Markdownを読み、構成・文面・出典・時間を調べる | 差し替え漏れ、`lang`、話題名だけの見出し、見出しの長さ、箇条書きの数、本文の量、数値の出典、alt、色の直書き、同じ型の連続、推定時間 |
| `ovs deck check`（実測） | ヘッドレスChromeで描画し、位置と色を測る | はみ出し、枠での切れ、フッター・ページ番号との衝突、重なり、余白への侵入、見出しの行数、最終行の孤立、小さな文字、コントラスト、画像切れ、フォント未導入 |

- errorは必ず0にする。そのまま聴衆に見える不具合だから。
- warnは原則直す。直さない場合は理由を報告に書く（例: 引用は原文どおりの長さを保つ）。
- infoは判断材料。直すかは内容で決める。
- ルールの一覧と根拠は `ovs deck rules` で確認する。
- 直し方は「文章の整理→レイアウトの変更→スライドの分割→サイズの調整」の順に検討する。
- 直したら同じコマンドを再実行し、新しく保存された画像で確認する。修正前の画像を合格の証拠に使わない。

## 目視検査

機械検査は位置と色の問題を拾えるが、意味が伝わるかは判定できない。`--shots` で保存した画像を全ページ見る。

1. 25%一覧（`contact-sheet.png`）で全体の流れ、型の偏り、密度の緩急、縮小しても主張と構造が分かるかを見る。
2. 各ページの画像（`slide-NN.png`）で枠の付いた指摘箇所と次の項目を見る。
   - 3秒で要点を言えるか。
   - 意図した改行と文字の収まり、図形・矢印・注釈の重なり。
   - 出典・ページ番号・図表の読みやすさ。
   - 日本語の欠字（豆腐）や意図しないフォント。
3. 作った本人の目には描いたものではなく意図したものが映る。
   ノートや元資料を読まずに画像だけを見て、初めて見る聞き手として判定する。

避ける項目: 全体を縮小した読めないスクリーンショット、解釈を示さない複雑なグラフ、
内部URL・個人名・識別子の持ち込み、一つの事例の無条件な一般化。
OVSのlint成功（図解素材の検査）だけでスライド全体の表示を合格にしない。

## リリースブロッカー

一つでも当てはまれば完成としない。

1. 文字のはみ出し・切れ・重なりがある。
2. テンプレートの差し替え箇所（〈〉・TODO）が残っている。
3. 見出しが話題名だけになり、タイトル列から主張を追えない。
4. 外部の事実や数値に出典がない、または参考資料スライドと対応していない。
5. 確認できなかった数値や事実が残っている。
6. 本文が3秒で要点をつかめない量になっている（発表モード）。
7. 画像のaltがない、または画像を読み込めない。
8. 濃色背景や注釈の文字が読めない。
9. 推定時間が持ち時間を超えている（発表モード）。
10. 最後のスライドが挨拶だけになり、持ち帰る一文と次の行動がない。

## 採点表

重要な発表や大きな資料では完成前に次の5観点を1〜5で採点し、3以下の観点を直す。
報告には点数の羅列ではなく、3以下だった観点と直した内容を書く。

| 観点 | 5の状態 |
| --- | --- |
| 聞き手への適合 | 対象者が知りたいこと・決めるべきことに答え、不要な前提説明がない |
| 正確さ | すべての数値・事実が出典と一致し、言える段階を超えた主張がない |
| 内容 | 1枚1メッセージ。証拠が主張を支え、画面の文字が最小限 |
| 見た目 | 型が役割に合い、階層・余白・配色が一貫し、表示の不具合がない |
| 流れ | タイトル列だけで話が通り、つなぎが自然。冒頭と結びが機能している |

## 発表準備

- ノートを台本にする（[slides-story.md](slides-story.md)「発表者ノート」）。`marp --notes slide.md -o notes.txt` で書き出せる。
- `ovs deck outline --minutes N` の推定時間を持ち時間の9割に収める。超えたら話す内容を削る。画面の文字を増やして補わない。
- 一度は声に出して通し、実際の時間を測る。推定と実測の差が大きいスライドを直す。
- 意思決定の資料は想定質問の付録を用意し、どの質問にどのスライドで答えるかを決めておく。
- HTMLで発表するなら、発表者ビュー（`p` キー）でノートが表示できることを事前に確かめる。

## 報告

1. 編集用Markdownと依頼された成果物へのリンクを示す。
2. 中心メッセージ、推定時間、自己紹介の判定を1行ずつ添える。
3. 実施した検証（lint・checkのerror/warn件数、目視したページ）と、直さなかったwarnの理由を伝える。
4. 未確認の項目を分けて伝える。ブラウザーを使えず画像を確認できなかった場合は生成成功と目視未確認を区別する。
5. プレビューアプリの自動起動はユーザーから求められた場合だけ行う。

## 発表後の改善

発表後24時間以内に次を記録し、次の資料と指針の改善に使う。

- 実際の所要時間と、時間が延びたスライド
- 詰まった説明、言い直した箇所
- 受けた質問（資料で先に答えるべきだったものに印を付ける）
- 反応が良かった・悪かったスライド

同じ問題が2回起きたら指針か検査ルールへ反映する（[slides-sources.md](slides-sources.md)「更新の手順」）。
