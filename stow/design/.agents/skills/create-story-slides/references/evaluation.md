# スライド制作の実践評価

構成・自己紹介・表現の選択や検証手順を変更したときに使う。
OVSの単体テストは検査器を確かめるものなので、実際の制作判断も別に確認する。

## 入力と実行方法

入力は [requests.json](../evals/requests.json) の3依頼。
既存デッキ短縮の素材は [legacy-deck.md](../evals/fixtures/legacy-deck.md)。
人物と数値は架空の検証用データであり、実績や実プロフィールとして再利用しない。

1. 独立した評価者へスキル本体、依頼、必要な素材だけを渡す。
   実運用に適用する文体・公開範囲などの環境条件も渡す。
   この採点基準や期待する修正案は先に渡さない。
2. 一時ディレクトリを作り、依頼ごとに原稿、出力、構成理由、検査記録を分ける。
   実プロフィールの読み取り、公開、外部リポジトリの変更は行わない。
3. 制作後に原稿と全ページの画像を確認し、下記を採点する。
   合格・要修正・未確認を区別し、失敗にはページ番号か該当コマンドを記録する。
4. 失敗の原因を指針か実装へ反映し、影響するケースを再確認する。
   同じ制作物の修正後確認と、新しい評価者による再制作は区別する。

## ケース別の観点

| ケース | 確認する判断 |
| --- | --- |
| 社外5分LT | 初対面に合う自己紹介。架空データの明示。比較条件と因果関係の限界。人数の提案と実績の区別。次のPRで行う記録への接続 |
| チーム内の定性共有 | 不要な人物紹介の省略。実測効果や画面の捏造なし。定義は簡潔な文章。関係の説明に適した図。観察と推測の区別 |
| 既存資料の短縮 | OVSテーマ・HTML・表紙と人物紹介の保持。重複説明の整理。新しい事実の追加なし。変更前後の構成・枚数と短縮理由の説明 |

全ケースで、中心メッセージの一貫性、本文の可読性、選んだ表現の役割、
持ち時間に応じた構成と枚数、要求形式の出力、機械検査と全ページの目視を確認する。
画像やアイコンの枚数、固定の言い回し、一律のレイアウト数は採点基準にしない。
台本作成・ノートの充足・読み上げ時間は評価対象にしない。
既存のノートや出典メモを保持し、必要な出典が追跡可能かを確認する。

## 評価記録

日付、対象差分、依頼ID、成果物の場所、実行した検査、残る警告、
採点の根拠と未確認項目を残す。一時成果物の保存期間は保証しないため、
再現には上記の入力を使う。3例の合格をあらゆる依頼への品質保証とは扱わない。

直近の確認内容は [実践評価の記録](../evals/results.md) を参照する。
